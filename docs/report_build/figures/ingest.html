Ingestion

How a PDF enters the corpus

Sixty crawled PDFs are in the stored artifacts. The live index has no uploaded_pdf rows.

1

Choose the entry

ingest --pdf copies one upload into data/raw. ingest-all reads every PDF there. process-pdfs reads the download manifest in data/pdfs.

IN a path or a directoryOUT a list of files
run.py
2

Bad files stop that document only

A missing path, an unreadable file, a corrupt PDF, or a PDF with zero pages raises. In a batch, that file is recorded under failures and the next file continues.

IN pathOUT FileNotFoundError, OSError, PdfReadError, or ValueError
PDFProcessor.process_pdf
3

Identity comes from the bytes

document_id = SHA-256 of the file. The file name becomes document_name. Crawled files also keep the URL, parent URL, and depth.

IN bytesOUT document_id and lineage
generate_document_id · process_pdf
4

Write the artifact, index later

The CLI writes one JSON artifact under data/extracted. Embeddings are created afterwards by python run.py index, together with summaries.

IN DocumentModelOUT PageContentArtifact JSON
ingestion.process_pdf
5

The other entry indexes immediately

PDFRAGPipeline.ingest_pdf embeds during the same call and can index the chunks. It does not build summaries. The live index contains summaries, so it was filled by the CLI index command.

IN PDFOUT IngestResult
PDFRAGPipeline.ingest_pdf
