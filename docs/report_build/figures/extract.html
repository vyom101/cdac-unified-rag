Extraction loop

What happens on each page

The cyber-forensics sample, 82f38954477f2c53.pdf, came through this loop as 25 successful pages and no OCR flag.

1

Open with pypdf

PdfReader supplies the page count, the information dictionary, and extract_text. The project does not reorder columns.

IN PDFOUT reader.pages
PDFProcessor.process_pdf
2

Clean that page

Control characters, hyphenated line breaks, repeated spaces, and running headers after page 1 are handled before the OCR test.

IN raw stringOUT cleaned string
clean_extracted_text
3

Is the page almost empty?

Fewer than 15 non-space characters sets requires_ocr. OCR replacement happens only when the recognised text is no longer that short.

IN cleaned textOUT SUCCESS or IMAGE_ONLY
check_requires_ocr
4

Split into blocks

A blank line starts a new block. A short block that looks like a heading is typed heading. Everything else is a paragraph.

IN page textOUT BlockModel list
detect_block_type
5

Keep images beside the page

PyMuPDF saves an embedded image of at least 50×50 pixels. The 60 stored PDFs produced zero image chunks.

IN page imagesOUT ExtractedImage files
OCRPageContext.extract_page_images
6

One bad page does not stop the file

An exception on a page stores extraction_status FAILED for that page. Document status is SUCCESS when failed_pages is 0, even if some pages are IMAGE_ONLY.

IN 1,479 pagesOUT 0 failed, 31 IMAGE_ONLY
stored extraction metadata
