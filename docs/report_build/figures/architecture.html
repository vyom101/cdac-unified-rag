Read from the top

What each layer receives and returns

A question never sees the whole PDF. It sees the five chunks that survive retrieval, plus the source list copied from those hits.

1

Response

The caller receives one RAGAnswer: the prose, the abstain flag, and the source list.

IN RAGAnswerOUT CLI JSON, or POST /ask JSON
run.py ask · rag/ui.py · PDFRAGPipeline
2

Generation

The ask path checks the gate, builds the prompt, and calls the client at temperature 0.

IN top hitsOUT answer text
answer_question · grounding_failure · get_llm_client
3

Ranking

BM25 and vector lists are normalised separately, fused 0.3 / 0.7, then cut to 5.

IN two pools of 20OUT 5 HybridSearchResult rows
fuse_hybrid_results
4

Retrieval

The same question is sent to a keyword match and to a cosine kNN query.

IN query stringOUT scored hits
BM25Retriever · VectorRetriever
5

Index

rag_corpus_v1 holds the words, the page list, and a 384-float cosine vector.

IN IndexableRecord + vectorOUT _id = chunk id
ElasticsearchIndexer.index_records
6

Embeddings

The active encoder is local all-MiniLM-L6-v2. Mock and custom HTTP providers also exist.

IN chunk textOUT 384 floats
LocalEmbeddingProvider
7

Chunks and lineage

Headings close a section. Pages, the file hash, and the chunk id stay on the record.

IN blocksOUT ChunkModel list
Chunker.process_document
8

Extraction

pypdf reads each page. A sparse page can go to Tesseract. Images use PyMuPDF.

IN PDF bytesOUT DocumentModel
PDFProcessor · OCRProcessor

The live index also contains HTML and summary rows because kb.source is all. A PDF-only question passes sources=pdf.
